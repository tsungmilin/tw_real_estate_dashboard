# 資料來源與更新

本文件是資料來源角色、內政部官方入口、發布批次識別及原始檔保存規則的權威來源。欄位與排除規則見 [資料清理與欄位契約](data-contract.md)，實際執行命令見 [PostgreSQL 資料流程與操作](database-operations.md)，目前已載入的批次見 [專案進度](project-status.md)。

## 1. 來源如何組成目前資料

目前資料不是用 MOI 全歷史重新建立，而是由兩類來源依序組成：

| 來源 | 角色 | 更新方式 |
|---|---|---|
| `data/raw/house_preowned_data_2.0.dta` | 2012–2024 年初始歷史底稿 | 保留原檔，不覆寫 |
| 內政部（MOI）買賣資料 ZIP | 後續新增、較早月份補登及既有案件修訂 | 每個發布批次獨立封存、清理並新增或更新 |

DTA 是由實價登錄資料整理而成的既有資料檔，不是本專案直接從內政部網站下載的原始批次。它只提供初始狀態，不代表舊月份永久凍結。MOI 新批次若包含較早月份的新交易識別碼，仍會補入；相同識別碼則由較晚發布批次更新。

本專案不重新散布 DTA、MOI 原始 ZIP、清理後 Parquet 或逐筆交易資料。公開內容只包含程式、聚合結果、文件、儀表板與資料品質摘要。

## 2. 內政部官方來源

| 用途 | 官方入口 | 說明 |
|---|---|---|
| 查詢與公告 | [內政部不動產交易實價查詢服務網](https://lvr.land.moi.gov.tw/) | 查詢成交案件及各期更新公告 |
| 當期批次下載 | [不動產成交案件實際資訊資料供應系統](https://plvr.land.moi.gov.tw/DownloadOpenData) | 下載當期靜態批次資料 |
| 資料集與欄位資源 | [政府資料開放平臺：本期發布之不動產買賣實價登錄批次資料](https://data.gov.tw/dataset/25119) | 提供 CSV、XML 與欄位資源 |

查詢服務目前於每月 **1 日、11 日、21 日**更新。發布日期、登記日期與交易日期不同；同一批次可能包含較早交易月份的新增或修訂案件。

本專案只處理買賣主檔 `*_lvr_land_a.csv`。租賃、預售屋及 `_land`、`_build`、`_park` 明細檔不在目前範圍；若未來要使用，必須另訂欄位與分析契約。

## 3. 發布批次識別

一個發布批次代表內政部某次提供的一包 ZIP，不代表單一交易月份。

| 欄位／檔案 | 規則 | 用途 |
|---|---|---|
| `release_id` | 第一次使用官方發布日期 `YYYY-MM-DD` | 決定發布順序 |
| `revision` | 同日內容改變時依序使用 `r2`、`r3` | 保存修訂版，不覆蓋舊檔 |
| `period_end` | 官方發布月份的民國年月 `YYYMM` | 排除未來月份或錯誤日期 |
| `sha256` | ZIP 下載完成後計算 | 確認內容是否相同或被替換 |
| 原始檔目錄 | `data/raw/moi/releases/<release_id>/` | 保存可重現的來源檔 |
| 發布紀錄檔 | `data/raw/moi/releases/release_manifest.json` | 串接來源、清理、測試與正式發布結果 |

識別規則如下：

- 發布日期與 SHA-256 都相同：視為同一來源，不重複清理或發布。
- 發布日期相同但 SHA-256 不同：保留兩份，新的 `release_id` 加上修訂版，例如 `2026-09-21-r2`。
- `period_end` 依官方發布月份確認，不從 ZIP 中最大的交易日期推測。
- 批次依發布時間處理；前一批尚未完成 PostgreSQL 發布時，不處理下一批。
- 當期檔不是完整快照。本批沒有出現的既有交易，不視為刪除或撤回。

## 4. 交易期間規則

專案歷史起點固定為 2012-08。每次清理可接受的交易年月介於 2012-08 與該批次的 `period_end`，不要求交易年月等於發布月份，也不使用 2025-01 作為 MOI 資料下限。

這項規則允許較早月份的補登或修訂，同時阻擋晚於官方發布月份的錯誤日期。精確的日期解析與排除順序由 [資料清理與欄位契約](data-contract.md) 維護。

## 5. 保存與追溯

- 原始 DTA 與每個 MOI ZIP 都不可變、不可覆寫。
- 每個發布批次使用獨立的原始資料、處理結果與稽核目錄。
- 清理稽核保存來源 SHA-256、買賣主檔清單、`period_end`、輸入筆數、清理後筆數、排除筆數與原因。
- 發布紀錄檔保存 `release_id`、修訂版、不可變檔案位置、`cleaning_run_id`、測試／正式 `load_batch_id` 與 `analytics_run_id`。
- `release_id`、`cleaning_run_id`、`load_batch_id` 與 `analytics_run_id` 分別代表不同階段，不可互相取代。
- 第一版不保存每筆交易更新前的完整版本，也不自動處理官方撤回。

完整更新順序、停止條件與失敗重跑方式見 [PostgreSQL 資料流程與操作](database-operations.md)。
