# 資料來源與未來更新

本文件說明目前作品集使用的資料來源、內政部（MOI）官方入口、更新頻率與未來換源方向。欄位與排除規則見 [資料清理與欄位契約](data-contract.md)，目前資料快照見 [專案進度](project-status.md)。

## 1. 目前版本使用的來源

目前 Dashboard 使用 `data/raw/house_preowned_data_2.0.dta` 建立固定資料快照。此檔由內政部實價登錄資料整理而來，但不是本專案直接從 MOI 官網下載的原始批次檔，也不應描述成未加工的官方原始資料。

本專案不重新散布該 `.dta`、清理後 Parquet 或逐筆交易資料。公開內容以程式、聚合分析表、Tableau 可攜工作簿、Dashboard 截圖與可公開的資料品質摘要為主。

資料源自內政部地政司實價登錄資訊；本版使用由該資料整理的固定 DTA 快照，經本專案重新清理、驗證、聚合與視覺化。

## 2. MOI 官方入口

| 用途 | 官方入口 | 說明 |
|---|---|---|
| 查詢與最新公告 | [內政部不動產交易實價查詢服務網](https://lvr.land.moi.gov.tw/) | 動態查詢來源與每期更新公告 |
| 當期批次下載 | [不動產成交案件實際資訊資料供應系統](https://plvr.land.moi.gov.tw/DownloadOpenData) | 免費下載當期 Open Data 靜態批次資料 |
| 資料集與欄位資源 | [政府資料開放平臺：本期發布之不動產買賣實價登錄批次資料](https://data.gov.tw/dataset/25119) | 提供 CSV／XML 下載入口與 schema 資源 |

專案分析的是買賣交易，不納入租賃與預售屋。未來直接接 MOI 批次檔時，以各縣市買賣主檔 `*_lvr_land_a.csv` 為主要輸入；建物、土地與車位明細檔只有在新增分析需求時才需要接入。

## 3. 發布頻率與資料時間

MOI 查詢服務目前在每月 **1 日、11 日、21 日**更新各類成交案件資料。批次資料供應系統同步提供該期靜態 Open Data，因此較精確的說法是「每月三次發布」，不是每月一次。

發布日期、登記日期與交易日期不是同一件事。某一發布批次可能包含較早交易日期的新增或修訂案件，因此更新流程不能只下載與目標交易月份同名的批次。要重建截至某日的可靠快照，應先依發布順序納入截止日前所有需要的批次、處理同一案件的後續修訂，再依交易日期決定分析期間。

MOI 亦提醒，實價登錄只呈現已發生且被登錄的案件，不代表區域內所有不動產行情；建物條件、車位申報與特殊交易都可能影響單價。Dashboard 因此揭露分析母體、案件數與中位數口徑，不把結果解讀為品質調整房價指數。

## 4. 現況與未來資料流

```text
目前作品集
MOI 實價登錄衍生 DTA 固定快照
        ↓
既有清理 → Parquet → PostgreSQL → Tableau

未來版本
MOI 官方歷史／當期 ZIP
        ↓
批次清單、檢查碼、欄位結構檢查與案件修訂處理
        ↓
MOI 欄位轉接層
        ↓
既有清理契約 → Parquet → PostgreSQL → Tableau extract
```

目前清理流程所需的業務欄位可由 MOI 買賣主檔取得。換源工作會集中在 PostgreSQL 之前，包括讀取多個發布批次與縣市檔案、轉換中文欄位、拆解交易日期、保存縣市來源資訊、標準化都市土地使用分區，以及以最新發布批次為準處理同一案件的修訂。

只要輸出的 32 欄清理後 Parquet 契約維持不變，既有 PostgreSQL `staging`、`core`、`analytics` 與 Tableau 設計原則上可以沿用。

## 5. 未來換源方向

1. 建立 MOI 原始欄位、目前 DTA 欄位與標準欄位的對照。
2. 下載代表性歷史批次，驗證檔名、編碼、欄位與早期 schema 差異。
3. 新增 MOI 資料匯入轉接層與批次紀錄，同時維持既有清理欄位名稱。
4. 依發布順序處理同一案件的跨批次修訂，保存修訂稽核。
5. 重新執行來源完整性與資料分布比較，再輸出相同的清理後 Parquet 契約。
6. 對帳 PostgreSQL 三層資料與 Tableau KPI，最後自動重建可攜版 extract。

MOI 直接換源屬於下一版發展；目前作品集保留固定且已通過驗證的資料快照。
